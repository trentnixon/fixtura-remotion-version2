    Fixtura Assets — design prototype guide

    Automated sports-media overlays for grassroots clubs and associations. Launch: npm run design from repo root → http://localhost:3456/design/ (see design/.docs/getting-started.md).

    Your job: design reusable overlay templates (titles, type, rows, scores, metadata, sponsor strip) — not one-off posters. Optimise for variable real data: long names, missing logos, different counts, awkward colour pairs.

    Scope — overlays and titles only

    Design here:

    • Titles and asset-type labels
    • Typography hierarchy (scores, team names, metadata)
    • Foreground layout: cards, glass panels, rows, tables, roster lists
    • Sponsor strip structure (not sponsor artwork creation)
    • Logo frames and identity placement

    Not here — handled elsewhere in Remotion:

    • Backgrounds (photos, gradients, Generated, Luminance, textures, motion)
    • Player photography or cut-outs

    A neutral placeholder backdrop is allowed so overlays stay readable. It is not a background specification.

    Results layout reference (pass 1)

    Structural baseline for Weekend Results — design/.docs/results-layout-reference.md (reference image in design/.research/). Extract match-module rules; do not copy background or styling. Develop visual identity around this anatomy.

    Per-match reading order:

    1. Horizontal team comparison — full scores, logos, names beneath each group
    2. Outcome spanning both teams
    3. Batting panel + bowling panel (label by data role, not team side)
    4. Format/round bottom-left; venue bottom-right

    Club-biased mode filters performance entries, not team comparison balance. Do not assume left team = club. Both matches repeat the same internal structure.

    Full rules and checklist: design/.docs/design-system-brief.md

    Not a website — one frame

    Each prototype is a single 1080 × 1350 video/social poster frame, not a web page. HTML is an authoring preview; Remotion renders the same layout to video. The sidebar, tabs and handoff line are dev chrome only.

    Do not add: review footers, concept labels, fixture-ID captions, colour-provenance copy, or preview-mode links outside .design-social-canvas. Sponsor strip inside the canvas is part of the graphic.

    Hard constraints

    • 1080 × 1350 px portrait — single finished graphic, not app UI or website
    • 72 px safe margin; keep critical type/logos ~88 px from edges
    • 12-column grid, 24 px gutter, 8 px spacing unit
    • Mobile-first — main fact readable at feed size
    • Data accuracy — never invent or alter competition data
    • Colours — org primary + secondary only (+ black/white/neutrals)
    • Automatable — every element maps to a component or data field

    Design thesis

    Sports broadcast energy × SaaS restraint. Match-day authority — energetic but not chaotic, bold but not esports. Score-first hierarchy, large numerals, rhythm and compact labels. No fake stadium FX, flames, or decoration that beats names and scores.

    Principles

    1. 3-second comprehension — asset type, org, primary fact
    2. Score/outcome before ornament
    3. One dominant story per asset
    4. Reusable structure, adaptable styling per club
    5. Family consistency across asset types
    6. Calm confidence — editorial, not hype

    Platform default: Outfit (display/scores) + Heebo (metadata/body).

    Two org colours + black/white/neutrals. Assign dominant field, accent, surfaces, text. Fix contrast with structure — do not add random accent colours. Status = words and weight first, not red/green alone.

    Move approved overlay layouts from the design site into Remotion. Manual reimplementation — no HTML-to-React converter. Full runbook: design/.docs/remotion-handoff.md

    Scope: Overlays inside main content only — not backgrounds, placeholder imagery, or design-site chrome.

    Find your targets

    Implementation steps

    1. Template shell — src/templates/variants/{variant}/ + entry in src/templates/registry.tsx (PascalCase registry ID)
    2. Composition displays — per asset under src/compositions/cricket/{composition}/; export lowercase routing key (e.g. scoreline) in src/compositions/cricket/index.tsx
    3. Theme mapping — theme/composition/{asset}.ts + theme/mode.ts + variant components; follow src/templates/variants/broadcastPro/.docs/readMe.md and design/design-Reference-docs/theme-modes.md
    4. Fonts — design/.docs/fonts.md (CDN in design → local in Remotion)
    5. Update manifest — replace TBD in routes.json and asset-index.md
    6. Verify — Remotion Studio with same fixture; appearance.template = registry ID; compare at 1080×1350

    Order for new variants: Results first, then result-single, then wider asset family.

    Tailwind, CSS, and styling

    Read before Pass 2 styling and again at handoff: design/design-Reference-docs/tailwind-css-remotion.md

    • Design site ≠ Remotion — CDN Tailwind / page CSS on prototypes does not copy automatically; Remotion uses Tailwind v4 via src/index.css
    • Where styles live — layout in literal Tailwind classes; reusable roles in theme/componentStyles; club/mode colours in hooks or style; motifs in variant CSS scoped to canvas root
    • Handoff-safe classes — complete strings only (gap-4); no dynamic assembly (bg-${color}); runtime values via style or CSS variables
    • Package CSS — custom variant stylesheets may need both src/index.css (Studio) and src/package/styles.css (distributed build)
    • Modes — Fixtura modes come from theme data, not Tailwind dark: — see theme-modes doc
    • Motion — frame-derived React styles only; no CSS transitions or timers

    Theme modes and contrast

    templateVariation.mode selects palette behaviour in Remotion. Club colours still supply brand backgrounds and accents; mode supplies container and text tokens. Full reference: design/design-Reference-docs/theme-modes.md

    Mode Container Title / copy without background Copy inside container
    light White Black Black
    lightAlt White White Black
    dark Black White White
    darkAlt Black Black White

    Alt flips title colour only — use for white headings over dark backdrops with light cards, or the reverse. Panel transparency uses shared tokens (subtle 30% → strong 85% opacity). Copy contrast is resolved against container.background; titles over transparent or moving backgrounds depend on what sits behind them.

    Exceptions: Scoreline (transparent light containers, adaptive context strip) and CNSW Private — see theme-modes doc. Verify all four modes in Studio, not only the design-site placeholder backdrop.
